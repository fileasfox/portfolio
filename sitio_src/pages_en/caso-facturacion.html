Project 08, real case, anonymised

Reproducible cleaning of billing data

Each client's fee and tech stack lived in a hand-maintained spreadsheet. To use them in the ROI analysis they had to be loaded into BigQuery without errors, and the load had to be repeatable every time the sheet changed.

PythonpandasRegular expressionsBigQuery

Problems in the original sheet

Formats

Decimals with commas and “TBC” values in numeric fields.

Inconsistent names

The same supplier written in several ways, and in-house builds with free-text descriptions.

Personal data

People's emails in a field meant to hold a company name.

Names that do not join

Hotel names did not match the database because of dates, codes and accents. The join had to be by ID.

How I solved it

  1. A script with a single input (the original sheet) and three outputs: the clean file, the excluded rows and a log of every change.

  2. Rules declared in an alias dictionary, so adding a new variant is one line.

  3. Join on the numeric ID; the name always comes from the hotel master table.

  4. Validation after loading: every ID exists in the master table, and active hotels without a fee are listed for review.

Result

More than 500 clients loaded with every key validated. The validation surfaced around twenty active accounts with no fee recorded, which went to billing for review. And the clean tech stack makes it possible to group technical failures by supplier in case 07.

Where it applies

Master spreadsheets with manual errors exist in every company. Turning them into a reproducible process is typical RevOps, finance and data quality work.
